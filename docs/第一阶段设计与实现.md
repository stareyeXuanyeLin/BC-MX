# BC Map Saver 第一阶段设计与实现

## 1. 第一阶段目标

第一阶段提供从“当前地图”到“本地存档”，再从“本地存档”恢复到“当前聊天室”的完整闭环：

1. 管理员保存当前地图；
2. 插件在浏览器本地管理多张地图；
3. 玩家可导入和导出单张地图或整个地图库；
4. 管理员将任意存档覆盖到当前地图房；
5. BC 服务器把新地图同步给房间内所有玩家。

## 2. 边界

### 2.1 插件负责

- 地图存档元数据；
- 本地持久化；
- 文件交换格式；
- 导入冲突处理；
- 地图模式入口和管理界面；
- 管理员权限检查；
- 应用前自动备份；
- 调用 BC 原生地图导入导出与同步后处理。

### 2.2 BC 原版负责

- 地图负载 Codec；
- 新旧地图格式兼容；
- `Tiles`、`Objects`、`Effects` 的实际解码；
- 房间属性网络同步；
- 玩家地图位置和原版碰撞修正。

### 2.3 第一阶段不做

- 云同步；
- 地图差异比较；
- 自制地图预览渲染器；
- 自动保存每次地图编辑；
- 修改 BC 地图 Codec；
- 保存或恢复玩家位置；
- 强制传送其他玩家；
- 因玩家位置无效而回滚地图。

## 3. 权限模型

插件入口仅对当前地图房管理员显示。

以下函数在执行时再次调用管理员检查：

- `saveCurrentMapAsNew()`；
- `overwriteSavedMapFromCurrent()`；
- `applySavedMapToRoom()`。

权限检查同时确认：

- `CurrentScreen === "ChatRoom"`；
- 通过词法标识符读取到的 `ChatRoomData.MapData.Type` 为 `Always` 或 `Hybrid`；
- `ChatRoomPlayerIsAdmin()` 返回 `true`；
- `ChatRoomMapManager.Map.exportString` 与 `importString` 可用。

界面隐藏属于体验层，业务层校验才是实际权限边界。

## 4. 数据模型

```ts
interface MapLibrary {
  schemaVersion: 1;
  records: LocalMapRecord[];
}

interface LocalMapRecord {
  id: string;
  name: string;
  note: string;
  createdAt: number;
  updatedAt: number;
  payload: string;
  sourceRoomName: string;
  mapType?: "Always" | "Hybrid" | "Never";
  storageVersion: 1;
  autoBackup: boolean;
}
```

`payload` 始终是 BC 原生 `exportString()` 的返回值。其他字段仅服务于插件本地管理，不参与地图解码。

约束：

- 最多 300 张地图；
- 单张原生负载最多 2,000,000 字符；
- 本地序列化结果最多约 4.5 MB；
- 单个导入文件最多 12 MB；
- 自动备份最多保留 10 张；
- 自动备份清理不会删除用户手动保存的地图。

## 5. 本地持久化

本地存储按账号隔离：

```text
BC.MapSaver.v1:<MemberNumber>
```

写入顺序：

1. 深拷贝当前地图库；
2. 在副本上执行变更；
3. 完整规范化所有记录；
4. 检查数量和序列化字节数；
5. 调用 `localStorage.setItem()`；
6. 写入成功后替换运行时状态。

因此 `QuotaExceededError` 等写入失败不会让内存状态先行改变。

读取到损坏数据时：

1. 保留原始主键内容；
2. 尝试复制到 `BC.MapSaver.v1:<MemberNumber>.corrupt.<timestamp>`；
3. 恢复副本成功后创建空地图库；
4. 恢复副本失败则禁止写入，避免覆盖唯一原始数据。

## 6. 文件交换

### 6.1 单张地图文件

```json
{
  "format": "BC_MAP_SAVER_MAP",
  "version": 1,
  "exportedAt": 0,
  "map": {}
}
```

### 6.2 地图库文件

```json
{
  "format": "BC_MAP_SAVER_LIBRARY",
  "version": 1,
  "exportedAt": 0,
  "library": {
    "schemaVersion": 1,
    "records": []
  }
}
```

### 6.3 原生字符串文件

如果导入文本不是 JSON，插件将其作为单张 BC 原生地图负载保存。由于本地导入阶段不会调用会修改当前房间的 BC `importString()`，最终有效性会在管理员应用地图时由 BC 原生解码器确认。

以 `{` 或 `[` 开始但无法解析的文本按损坏 JSON 报错，不会伪装成原生地图字符串。

## 7. 冲突策略

| 策略 | 行为 |
|---|---|
| 保留双方 | 导入记录生成新 ID；同名时追加“（导入 N）” |
| 按 ID 覆盖 | 相同 ID 的本地记录被覆盖，并保留本地创建时间 |
| 按名称覆盖 | 同名本地记录被覆盖，并保留本地 ID 与创建时间 |
| 跳过冲突 | ID 或名称任一冲突即跳过 |
| 替换整个地图库 | 清空当前记录后写入导入文件，仅对整库文件显示 |

所有策略先构建完整结果，再一次性持久化。

## 8. 应用地图

`applySavedMapToRoom()` 的执行顺序：

1. 检查当前地图房和管理员权限；
2. 调用 `exportString()` 捕获当前地图；
3. 将捕获结果写为自动备份；
4. 调用 `importString(target.payload)`；
5. 失败时删除本次未使用的自动备份并报告，BC 保证当前地图不被修改；
6. 成功时调用 `ChatRoomMapViewUpdateFlag()`；
7. 调用 `ChatRoomMapViewCalculatePerceptionMasks()`；
8. 等待 BC 原版延迟同步机制发送 `ChatRoomAdmin / Update`。

插件不直接构造 `ServerSend("ChatRoomAdmin", ...)`，以免复制服务器协议或遗漏未来新增的房间字段。

当前 BC 将 `ChatRoomData` 声明为顶层 `let`，将 `ChatRoomMapManager` 声明为顶层 `const`。它们能被后续脚本用同名标识符访问，但不会挂到 `globalThis`；插件通过兼容访问器优先读取词法绑定，再回退到旧版窗口属性。

## 9. 玩家位置

玩家位置属于：

```text
Character.MapData.Pos
```

它不属于房间地图文件。

地图覆盖后，如果某个未安装插件的玩家所在格变成不可站立位置，BC 原版 `ChatRoomMapViewCollision()` 会在她的地图视图绘制过程中尝试寻找：

1. 上下左右相邻格；
2. 四个对角格；
3. 距离两格的上下左右位置。

找到后由该玩家客户端更新并同步自己的坐标；找不到时继续停留在原格子。插件不对此增加跨客户端协议或全图搜索。

## 10. UI Hook

入口使用：

- `ChatRoomRun`：在原版聊天室与活动视图完成绘制后，于左侧 `(10, 500)` 绘制“档”按钮；
- `ChatRoomClick`：在原版点击分发前拦截对应坐标并打开 DOM 面板；
- `ChatRoomLeave`：离开聊天室时关闭插件面板。

不能只 Hook `ChatRoomMapViewDrawUi` 与 `ChatRoomMapViewClick`。BC 初始化 `ChatRoomViews.Map` 时已经捕获这两个函数的原始引用，后续替换同名全局函数不会改变活动视图保存的引用。

入口只在地图编辑模式为空字符串时显示，不占用原版地块、物件和效果选择界面的动态按钮区域。

管理面板使用独立 DOM，不接管新的 BC Screen，也不修改原版 Canvas 输入状态。所有确认、命名和冲突选择均使用插件内置对话框。
