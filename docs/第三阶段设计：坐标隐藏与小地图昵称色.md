# 第三阶段设计：坐标隐藏（捉迷藏）与小地图昵称色

## 背景与目标

- 插件用户可一键切换"隐藏坐标"状态，默认关闭（正常显示坐标与小地图标记）；
- 隐藏开启后，**插件 UI 层面**对其它用户隐藏：不显示该玩家的坐标，不绘制其小地图标记；
- 用户自己的插件视角一切照常（自己能看到自己的坐标与标记）；
- 房间成员列表中名字依然可见（原版列表与插件列表都是）；
- 游戏层面（BC 协议、原版地图视图）完全不做任何干预：不拦截消息、不伪造坐标、不停止广播；
- 小地图玩家标记颜色改为固定使用玩家昵称颜色（`Character.LabelColor`）。

## 为什么不需要动游戏协议

插件 UI 显示坐标的依据是 `ChatRoomCharacter[i].MapData.Pos`（广播维护的远端数据）。只要知道"谁开了隐藏"，UI 层过滤即可，网络层无需任何改动。

隐藏状态的传递方式：**直接挂在正常广播的 MapData 对象上**。R130 接收端验证器 `ServerAccountDataSyncedValidate.MapData` 对未知字段原样保留（`{...arg}` 展开），原版渲染只读 `Pos` / `PrivateState`，多一个自定义字段零影响。玩家每次移动都会广播完整 MapData，标记随之自然流转，不需要额外的消息通道。

## 现状链路（R130 源码确认）

### 发送端（本地玩家）

所有位置同步都广播完整 MapData 对象：

```text
移动完成 / 进地图 / 被传送 / leash 拉拽 / 500ms 节流
        ↓
ServerSend("ChatRoomCharacterMapDataUpdate", Player.MapData)
```

### 接收端（其它用户）

```text
ServerSocket "ChatRoomSyncMapData" → ChatRoomMapViewSyncMapData(data)
        → char.MapData = ServerAccountDataSyncedValidate.MapData(data.MapData, char)   // 未知字段保留
ChatRoomSyncCharacter（进房/重同步） → Character.js 同样经验证器写入
```

### 昵称颜色

`Character.LabelColor`（HexColor，同步时验证器保证合法，非法回退 `#ffffff`）；自己端读 `Player.LabelColor`。

## 方案设计

### 1. 发送端：标记字段 + 切换时主动广播

```js
// 隐藏状态（localStorage: BC.MapSaver.stealth:<MemberNumber>，默认 false）
function setStealthEnabled(enabled) {
    const mapData = Player.MapData;
    if (enabled) mapData.BMSHidden = true;
    else delete mapData.BMSHidden;
    // 立即广播一次：让所有插件端感知状态变化（原版移动广播会继续携带/不携带该字段）
    ServerSend("ChatRoomCharacterMapDataUpdate", mapData);
}
```

- 不 hook、不拦截 `ServerSend`，原版广播链路零改动；
- 开启后玩家正常移动，每次广播自然携带 `BMSHidden: true`；关闭后自然消失；
- 进房初始化（`ChatRoomMapViewInitializeCharacter`）验证器保留字段，标记跨进房/跨房间保持；
- 已知副作用：`ServerAccountUpdate.QueueData({ LastMapData: Player.MapData })` 会把标记字段存入账号数据，无害（验证器保留未知字段），且重登后状态自动延续；
- 本地 `Player.MapData.Pos` 从不改动，自己视角、移动、碰撞全部正常。

### 2. 接收端：识别标记，只改插件状态，不动游戏数据

```text
hook ChatRoomMapViewSyncMapData（实时位置更新）
hook ChatRoomSyncCharacter（进房 / 角色重同步）
    data.MapData?.BMSHidden === true
        → char.BMSHidden = true     // 仅插件侧标记
    data.MapData 无标记
        → char.BMSHidden = false
    char.MapData 照常写入（游戏层面完全正常）
```

关键区别：**不把 `char.MapData` 置空**。原版地图视图、其它插件、游戏逻辑全部照常，隐藏只作用于本插件 UI。

### 3. 插件 UI 过滤

- `getRoomCharacterList()` 增加可选过滤参数（渲染数据源过滤非自己且 `BMSHidden` 的玩家）；
- `drawMinimap`：跳过隐藏玩家（不画点、不画 hover 名字）；自己的标记永远绘制；
- roster：隐藏玩家显示名字 + `🙈 隐藏中` 标签，不显示坐标；自己的条目永远正常；
- `findRoomCharacterAt` / hover 状态：跳过隐藏玩家；
- 传送交互：roster 中隐藏玩家可点选但状态栏提示"该玩家已隐藏坐标"；传送落点仍可在 canvas 选择（游戏层面位置照常，管理员知道去哪找）。是否允许管理员传送隐藏玩家，待凡尘确认。

### 4. 切换按钮与状态

- 存储键：`BC.MapSaver.stealth:<MemberNumber>`，默认 `false`；
- 按钮位置（待凡尘确认）：
  - 小地图面板 header（与缩放/复位并排，眼睛图标）；
  - 地图模式左侧工具栏第二个按钮（与"图"按钮并列，不打开小地图也能切）；
- 切换动作：见第 1 节 `setStealthEnabled`，开/关各立即广播一次。

### 5. 小地图昵称色

```js
function minimapPlayerColor(character) {
    // 优先昵称颜色；非法/缺失回退哈希色
    return isHexColor(character?.LabelColor) ? character.LabelColor
        : MINIMAP_PLAYER_COLORS[Math.abs(Number(character?.MemberNumber) || 0) % MINIMAP_PLAYER_COLORS.length];
}
```

- 所有玩家（含自己）的点与 roster 圆点统一使用昵称色；
- 自己仍保留白色描边 + 头顶标识以便区分。

## 效果矩阵

| 观察者 | 插件 UI（小地图/坐标） | 游戏层面（原版地图） |
| --- | --- | --- |
| 装了插件、对方隐藏 | 不显示坐标、不绘制标记，名字 + "隐藏中" | 照常可见（协议无干预） |
| 未装插件 | 无插件 UI | 照常可见 |
| 隐藏玩家自己 | 正常显示自己的坐标与标记 | 照常 |

## 边界情况

| 场景 | 处理 |
| --- | --- |
| 隐藏状态下进房 | `InitializeCharacter` 广播带标记，插件端立即可识别 |
| 隐藏状态下被传送 / 被 leash | 广播带标记，插件端持续隐藏 |
| 广播丢失 | 接收端保持旧标记状态，下次广播纠正 |
| 重登/跨房间 | 标记字段随 LastMapData 延续；状态与 localStorage 双保险 |
| 同一房间多份插件实例 | 标记字段统一（`BMSHidden`），行为一致 |
| 服务器版本差异 | 服务器只转发 MapData；未知字段透传（与接收端验证器行为一致） |

## 测试要点

- 接收 hook：带 `BMSHidden` → 插件标记置位且 `char.MapData` 不被篡改；无标记 → 清除标记；
- UI 过滤：隐藏玩家不出现在 canvas 与坐标列；名字保留；自己不受影响；
- 颜色：合法 `LabelColor` 优先；`undefined`/空串/非法格式回退哈希色；
- 切换：开/关各触发一次广播，payload 携带/不携带标记。
